# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Solution Overview

`SpeiseDirekt3.sln` contains five .NET 9 projects:

| Project | Type | Purpose |
|---|---|---|
| `SpeiseDirekt3/` | Blazor Server web app | Restaurant back office (menus, categories, items, allergens, combos, QR codes, analytics, user management), public menu display and the landing page on `/` |
| `SpeiseDirekt.Api/` | ASP.NET Core Web API | REST API (Swagger, Identity API endpoints) over the same data |
| `SpeiseDirekt.Model/` | Class library (root namespace `SpeiseDirekt`) | Shared core: entities, DbContext, migrations, repositories, services, authorization, DI setup |
| `SpeiseDirekt.Api.IntegrationTests/` | xUnit test project | Integration tests for every API controller |
| `SpeiseDirekt3.E2ETests/` | xUnit + Playwright test project | Browser end-to-end tests for the Blazor app (public pages, QR resolution, auth, back office) |

Both `SpeiseDirekt3` and `SpeiseDirekt.Api` reference `SpeiseDirekt.Model` and share one SQL Server database (connection string `server`).

## Development Commands

Run from the repository root.

### Building and Running
- **Build everything**: `dotnet build`
- **Run Blazor app**: `dotnet run --project SpeiseDirekt3` (https://localhost:7051, http://localhost:5010)
- **Run Web API**: `dotnet run --project SpeiseDirekt.Api` (https://localhost:7254, http://localhost:5289; Swagger UI at `/swagger` in Development)
- **Watch mode**: `dotnet watch run --project SpeiseDirekt3`
- **Run Blazor app without SQL Server**: set `ASPNETCORE_ENVIRONMENT=E2E` (`Program.E2EEnvironment`): SQLite (connection string `e2e`, default `speisedirekt-e2e.db`), schema via `EnsureCreated()` (`E2EDatabaseInitializer`, no migrations), static web assets enabled. The database starts empty.
- **Preview environment** (`ASPNETCORE_ENVIRONMENT=Preview`, `Program.PreviewEnvironment`; the PR preview on server2 runs with it): production code paths plus `appsettings.Preview.json`. `Preview/PreviewSeedHostedService` runs `PreviewSeeder` at every start, i.e. right after the CI job copied the production database and applied the PR's migrations: for the user in `PreviewSeed:Email` (a sub-account seeds its owner's tenant) it adds three demo menus (`Preview: Gasthaus Zur Post` Classic with four categories (three with a subtitle), 13 items, six allergens, a combo, item labels, price variants on the drinks and extras on two dishes; `Preview: Mittagskarte` Modern; `Preview: Bar & Lounge` Dark), five QR codes (`Preview: Tisch 1`, `Preview: Mittag`, `Preview: Bar` direct; `Preview: Eingang (Zeitplan)` time table; `Preview: Tagesaktion (Kalender)` calendar) and, only when the tenant has none, a restaurant profile "Gasthaus Zur Post" (links to `https://example.com`). Idempotent by name: a menu or QR code that already exists in the tenant is left alone (not enriched either), an existing profile is never touched. Unknown e-mail = nothing happens, a failure is logged and the app starts anyway, `PreviewSeed:Enabled=false` switches it off. The CI step "Preview-Seed prüfen" prints the journal line.
- **Manual API requests**: `SpeiseDirekt.Api/SpeiseDirekt.Api.http`

### Testing
- **Run all tests**: `dotnet test`
- **Run a single test class**: `dotnet test --filter "FullyQualifiedName~MenusControllerTests"`
- **Run a single test**: `dotnet test --filter "FullyQualifiedName~MenusControllerTests.GetAll_ReturnsSeededMenus"`
- **Run only the E2E tests**: `dotnet test SpeiseDirekt3.E2ETests` (no SQL Server needed; Chromium is installed by Playwright on first run, or set `PLAYWRIGHT_CHROMIUM_EXECUTABLE` to an existing binary)

### Database Operations
Migrations live in `SpeiseDirekt.Model/Data/Migrations`, so the EF commands need both project flags:
- **Create migration**: `dotnet ef migrations add <MigrationName> --project SpeiseDirekt.Model --startup-project SpeiseDirekt3`
- **Update database**: `dotnet ef database update --project SpeiseDirekt.Model --startup-project SpeiseDirekt3`
- **Remove last migration**: `dotnet ef migrations remove --project SpeiseDirekt.Model --startup-project SpeiseDirekt3`

Build of the merge commit (master + PR), tests, copy of the production database to `speisedirekt-pr-preview` (`deploy/preview/db-kopie.sql`, run with `sa` from the CI host), migrations against the copy, `speisedirekt-preview.service` (user `sdpreview`, port 5013) on server2, comment in the PR with the applied migrations. `workflow_dispatch` with a PR number redeploys a preview by hand.

## Architecture

### Technology Stack
- **Framework**: ASP.NET Core 9.0 (Blazor Server: the back office is Interactive Server, the guest pages and the landing page are static SSR; Web API with controllers)
- **Database**: SQL Server via Entity Framework Core 9 (split queries enabled)
- **Authentication**: ASP.NET Core Identity. Cookies in the Blazor app; `AddIdentityApiEndpoints` / `MapIdentityApi` in the API
- **UI**: back office: Tailwind CSS via the Play CDN `cdn.tailwindcss.com` (config inline in `SpeiseDirekt3/Components/App.razor`: the palettes `brand` (alias `primary`) and `accent` map to the variables of `css/brand.css`) — the **only** remaining external asset, and never loaded on the guest pages or the landing page (they have their own CSS/JS, see *Guest pages* and *Landing page*). Everything else is in the repo: Bootstrap 5.3.3 (`wwwroot/lib/bootstrap`), Chart.js 4.6.1 + chartjs-adapter-date-fns 3.0.0 (`wwwroot/lib/chartjs`, analytics page), FullCalendar 6.1.22 standard bundle (MIT, `wwwroot/lib/fullcalendar` with LICENSE and a README: tarball URL, `dist.integrity`, how it was verified, why not 7.x; byte-identical to the tarball via `.gitattributes`; loaded lazily by the calendar wrapper only, never on guest pages), fonts (`wwwroot/fonts`, `css/fonts.css`: Inter, Manrope and the theme fonts, woff2, latin + latin-ext, SIL OFL licenses in `fonts/licenses`). Icons are inline SVGs (no icon font).
- **AI**: Microsoft.Extensions.AI with Ollama (`llama3.2:latest` at `http://localhost:11434`, hard-coded in `SpeiseDirekt3/Program.cs`)
- **Images**: SixLabors.ImageSharp for resizing; images are stored as bytes in the database (`Image` entity)
- **QR codes**: QRCoder (PNG generated in `SpeiseDirekt3/Controller/ImageController.cs`)
- **Tests**: xUnit, FluentAssertions, `WebApplicationFactory`, SQLite (in-memory for API tests, temp file for E2E), Microsoft.Playwright

### SpeiseDirekt.Model (shared core)
- `Model/Model/`: one file per entity
  - `Menu` (with `DesignTheme`: Elegant, Modern, Classic, Minimal, Fancy, Dark — styles the guest view, see below; `MenuLanguage` (21 values); and `TranslationGroupId` (`Guid?`, migration `AddMenuTranslationGroup`): menus with the same group id are **language versions** of each other, at most one per language — filtered unique index `(TranslationGroupId, Language)` where the id is not null, on SQL Server and SQLite; managed only by `IMenuTranslationService`) → `Category` (optional subtitle `Description`, ≤ 200) → `MenuItem` (labels `IsVegan`, `IsVegetarian`, `IsSpicy`, `IsHalal`, `IsAlcoholFree`, `IsNew`, `IsPopular`; `Description` is optional). `Category` and `MenuItem` carry `SortOrder` (migration `AddCategoryAndMenuItemSortOrder`, default 0): every list, the guest display and the API order by `SortOrder` then name through `Infrastructure/DisplayOrder.cs`; new entries get last + 1 within their parent, the back office reorders by drag handle (`Shared/Sortable/SortableList`, AP11).
  - `MenuItemPriceOption` (migration `AddRestaurantProfileLabelsAndPriceOptions`, cascade with its item): `Kind` `Variant` (alternative size/version with its own price, e.g. "0,25 l" / "0,5 l") or `Extra` (optional add-on, e.g. "+ Halloumi"; JSON `"Variant"`/`"Extra"`), `Name` ≤ 60, `Price` ≥ 0, `SortOrder` within its kind. **Rule:** an item with at least one variant has `Price` = the lowest variant price (`Infrastructure/PriceOptions.ApplyLowestVariantPrice`, applied by the item editor, the API and the seeders), so ordering, combos and old clients keep a meaningful price; guests read it as "from € x".
  - `RestaurantProfile` (one per tenant, unique `ApplicationUserId`): `Name` (required), `Description` ≤ 1000, `LogoImagePath`/`CoverImagePath` (stored like `MenuItem.ImagePath`, `image/{id}`), `Phone`, `Email`, `Website`, `InstagramUrl`, `FacebookUrl`, `GoogleReviewUrl` (absolute http/https, `[HttpUrl]`/`[OptionalEmail]` in `ValidationAttributes.cs`, empty allowed), `Address` and `OpeningHours` (multi-line free text). Stored trimmed, empty → null, line breaks `\n`.
  - `Allergen`: belongs to a menu (`MenuId`, short `Code` + `Name`); many-to-many with `MenuItem` via join table `MenuItemAllergen`
  - `MenuCombo` / `MenuComboItem`: combo offers per menu, triggered by a `TriggerMenuItem`, with a `ComboPrice` and a list of included items
  - `QRCode`: points to a menu directly, or is time-table based (`TimeTableEntry`) or calendar based (`CalendarEntry`). `IValidatableObject` checks for overlapping time windows and date ranges.
  - `TenantSubscription`: paid vs. free tier, `MaxUsers`, `PlanName`
  - `Image` (immutable bytes; **may be referenced by several items** — a language copy points to the original's photos — so never delete an `Image` when an item or menu is deleted without checking references; today nothing does, replacing a photo uploads a new one), `TranslationCache`
  - Analytics: `MenuView`, `MenuItemClick` (not tenant-scoped, FKs with `NoAction`)
- `Model/PermissionModels.cs`: `TenantRole`, `[Flags] Permission` enum, `TenantUser` (sub-account of a tenant)
- `Model/Dto/`: shared DTOs (`CreateMenuItemDto`, `BreadcrumbItem`)
- `Data/ApplicationDbContext.cs`: Identity DbContext, global query filters, relationship config, automatic `ApplicationUserId` assignment
- `Data/ApplicationUser.cs`: Identity user with `TenantOwnerId` (null = tenant owner, set = sub-account)
- `Infrastructure/ServiceExtensions.cs`: `ConfigureServices()` registers the shared services and repositories (DbContext-dependent ones as `Transient`). Both hosts call it.
- `Infrastructure/`: authorization (see below), `TenantClaimsTransformation`, `CalendarSchedule` (**the one place for the calendar rules** of a calendar-based QR code: `IsActiveOn(entry, date)`, `ActiveEntry(entries, date)` — one-off (date or period) before weekly, then the earliest `Date`, input order on a tie —, `Collide(a, b)` — only entries of the same kind: two periods sharing a day, two weekly entries on the same weekday with overlapping periods —, `Conflicts`, `HasEndBeforeStart`; used by `MenuService`, `QRCode.Validate` and the back-office calendar), `EditFormExtensions`, `DisplayOrder` (ordering helpers), `PriceFormat.Euro` (back-office prices as `€ 13.90`, invariant culture; the guest view uses `GuestFormat.Price` with `€ 13,90`), `ItemLabels` (**the one list of item labels**: stable `Key`, property, English back-office text, German and English guest text (`GuestTextFor(german)`), `Dietary`/`Highlight`, display order; `ActiveFor(item)` applies "vegan hides vegetarian", `Matches` lets a vegan item count as vegetarian in filters; editor, item table, guest view and guest filter all read it), `PriceOptions` (`Variants()`/`Extras()` in display order, `HasVariants`, `ApplyLowestVariantPrice`, `Renumber`), `GuestMenuQueries.IncludeGuestContent()` (categories → items → allergens and price options in order, for guest pages), `ImagePaths` (`image/{id}` ↔ id, API URL `/api/images/{id}`), `MenuLanguages` (**the one table of menu languages**: per `MenuLanguage` the ISO code for `lang`/`hreflang`, the endonym ("Deutsch", "Français", "日本語"), English and German name, `og:locale`; `InLanguageOrder`), `EuAllergens` (the 14 EU allergens A–R with German/English names; `NameIn(language, code, name)` renames a standard name for a copy)
- `Repository/`: repositories for Menu, Category, MenuItem, QrCode, Image and MenuCombo (used by the API)
- `ServiceInterface/` and `ServiceImplementation/`: services (see below)

### Multi-Tenant Architecture
- A **tenant** is the owner account. Sub-accounts (`ApplicationUser.TenantOwnerId` set, plus a `TenantUser` row with role and permissions) work on the owner's data.
- Tenant-owned entities implement `IAppUserEntity` (`ApplicationUserId` = tenant owner ID).
- `ApplicationDbContext.OnModelCreating` applies global query filters on `ApplicationUserId` for MenuItem, Category, Menu, QRCode, TimeTableEntry, CalendarEntry, Allergen, MenuCombo, MenuComboItem, MenuItemPriceOption and RestaurantProfile.
- `ChangeTracker` events set `ApplicationUserId` on Added/Modified entities from `IUserIdProvider`. Adding, modifying or deleting an `IAppUserEntity` **throws** if no authenticated user is present; merely tracking queried entities (anonymous public pages) is allowed.
- `TenantClaimsTransformation` adds `TenantOwnerId` and `TenantRole` claims for sub-accounts.
- `IUserIdProvider.GetUserId()` returns the **tenant owner ID** (the `TenantOwnerId` claim for sub-accounts, otherwise `NameIdentifier`) and is what the query filters use. `GetActualUserId()` returns the logged-in user. Both return `Guid.Empty` when unauthenticated.
- Public/anonymous paths (QR code resolution, public menu display) use `IgnoreQueryFilters()`. See `MenuService`, `MenuDisplayPage.razor`, `QrRedirect.razor`. The owner preview `/menu/preview/{id}` (`MenuPreviewPage.razor`) is `[Authorize]` and uses the query filters (own tenant only); it renders with `TrackClicks = false` so item clicks are not counted in the analytics.

### Authorization
- **Permissions**: `Permission` is a `[Flags] long` enum (`MenusView`, `MenusCreate`, …, `UsersDelete`, `DeliveryView`, …). When adding a value, pick an unused bit; the bits are not in order.
- **Policies**: `AuthorizationOptions.AddPermissionPolicies()` generates one policy per permission, named `Can{Action}{Area}` (e.g. `MenusView` → `CanViewMenus`). `PolicyNames` holds constants for them; they must match `GetPolicyName` (e.g. `CanViewMenuCombos`).
- **Resolution** (`PermissionService`): the owner has all permissions. A sub-account uses `TenantUser.Permissions` if set, otherwise the role defaults from `PermissionDefaults` (GeneralManager, Manager, Cashier, Employee, Driver). Inactive or missing `TenantUser` → no permissions.
- **API**: controllers use `[Authorize(Policy = PolicyNames.Can…)]` per action. `ImageUploadController` and `MenuDisplayController` have no permission policies.
- **Blazor**: pages use `@attribute [Authorize]` and check `IPermissionService.HasPermissionAsync(Permission.…)` to show/hide actions. `/qrcodes` without `QrCodesView` redirects to `/Account/AccessDenied`. `/qrcode/edit/{id}` without `QrCodesEdit` but with `QrCodesView` (e.g. Cashier) opens **read-only** (notice, fields disabled, no Save, the calendar without panel or dragging; `/qrcodes` shows "View" instead of "Edit"); a new code still needs `QrCodesCreate`.
- **PaidTenant** policy (`PaidTenantHandler`): passes for tenants with an active paid `TenantSubscription`; free tenants pass while they have fewer than 100 QR codes. `/qrcodes` disables the "Create New QR Code" button, and `/qrcode/edit` checks it as well (on load for a new code and again on save; editing existing codes stays allowed).
- **User limit**: creating a sub-account fails once the active `TenantUser` count reaches `TenantSubscription.MaxUsers`.

### Key Services
- **IMenuService**: resolves the active menu for a QR code. Precedence: matching calendar entry for today (if `IsCalendarBased`, `CalendarSchedule.ActiveEntry`), then the active time-table window (if `IsTimeTableBased`, also across midnight; no active window = null), otherwise the direct menu. Uses the injected `TimeProvider` (`GetLocalNow()`), registered as `TimeProvider.System` in `ServiceExtensions`.
- **IPermissionService**: current role and permissions (cached per instance)
- **ITrackingService** / **IAnalyticsService**: records menu views and item clicks (session cookie `SpeiseDirekt_SessionId`) and aggregates them for the analytics page and API.
- **IImageUploadService**: `ImageDatabaseUploadService` (registered in the Blazor app) stores images in the DB and returns `image/{id}`; `DeleteImageAsync` takes that path (or the bare id). `ImageUploadService` (file-based, `wwwroot/uploads/`) still exists but is not registered.
- **IRestaurantProfileService**: `GetForOwnerAsync(ownerId)` / `GetForMenuAsync(menuId)` for anonymous guest pages (`IgnoreQueryFilters`, `AsNoTracking`, null when none; owner = `Menu.ApplicationUserId`; `GuestMenuLoader.BuildAsync` calls `GetForOwnerAsync` once per request, also in the preview), `GetOwnAsync()` and `SaveOwnAsync(values)` (create or update, normalizes and validates, returns whether it was created) for the back office and the API.
- **IMenuTranslationService** (`MenuTranslationService`, back office + API, tenant query filters): `GetVersionsAsync` (the group in language order, the menu included), `GetLinkCandidatesAsync` (menus in a free language that are not linked elsewhere), `CreateTranslationAsync(menuId, language)` ("Add translation": copies name → "X (English)" (unique, a language suffix is replaced, then " 2", …), description, theme, categories, items with every field/label/sort order/price option/photo reference/allergen link, the menu's allergens (EU standard names in the target language, own names unchanged) and combos into new rows, links both menus; one `SaveChanges`; no QR code), `LinkAsync`, `UnlinkAsync` (a group left with one menu is dissolved), `ValidateLanguageAsync` (message when another version has the language). `LeaveGroupOnDeleteAsync` is called by both menu deletes (back office, API): the others stay linked, a single one left is unlinked. No machine translation (owners translate the copy by hand).
- **IImageResizeService**: resizes uploads (ImageSharp)
- **IMenuItemGenerator**: AI-generated menu items via Ollama (Blazor app only)
- **IAutomaticTranslator** / **ITranslationApiService**: Azure Translator with DB cache (`TranslationCache`), incl. allergen names. Implemented but not registered or used (operator decision: key and cost; language versions are translated by hand).
- **INotificationService**: in-app notifications
